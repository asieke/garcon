Install

Start locally, then connect your tools.

Garcon supports macOS and Linux on x64 and arm64. Node 18+ runs the npm command; the background service is a standalone binary. Run setup as your normal user.

Install
npm install -g ai-garcon@latest
garcon setup

Setup starts Garcon at login. Open Providers, add accounts, and copy your tool's settings. Restart it, send a request, and check Logs. Your history is preserved.

Try it without a service

npx ai-garcon@latest runs in the foreground. If Linux has no user service manager, run garcon in one terminal and garcon setup --no-service in another.

Update

npm installation
garcon update
garcon doctor --wait 10s

Finish in-flight requests first: the proxy restarts. The update keeps local data and refreshes the service's private binary. Older versions can use npm install -g ai-garcon@latest, then garcon service restart.

When it doesn't connect

Run garcon doctor and garcon service status. If the command is missing, check your npm bin directory on PATH. type -a garcon finds competing installs. For permission errors, use a Node version manager or a user-owned npm prefix.

macOS logs: ~/Library/Logs/garcon.log. Linux logs: journalctl --user -u garcon.

From source

Use Go 1.27+ and Node 22+, then run scripts/install.sh --service. Later, scripts/install.sh --update pulls and rebuilds a clean checkout.

Production uses 4141. bash scripts/dev.sh builds and runs development on 4242. For frontend hot reload, run npm run dev:frontend from web/; it uses the installed backend. Both modes use real local data. Development builds don't update production.

Remove it

Restore your tools' original provider URLs first. Then run garcon service uninstall and npm uninstall -g ai-garcon. Your usage and settings remain.

Keep the default loopback binding. Garcon has no app login; -allow-remote opens a view-only dashboard and the relay to the network. All dashboard changes are rejected, including from localhost and reverse proxies. Use garcon accounts, garcon providers, and garcon routing locally on the server. The private CLI socket is created alongside the database.
